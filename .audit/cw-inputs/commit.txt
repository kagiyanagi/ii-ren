refactor(cw-inputs): the state a keyboard leaves no trace of, and a thumb that is not a fade

Not one of the seven shared value controls read `visualFocus` or rendered
`activeFocus`. Sliders, switch, radio, both combo boxes and the spin box shipped
hover and press and stopped, which means a Tab through the settings app -- built
almost entirely out of these -- moved a focus ring that did not exist. The
mechanism is split by what the control is: `visualFocus` for anything you click,
so a mouse press does not leave a film behind, and `activeFocus` for anything
you type into, because a text field that was clicked into is focused and 3.7
names that case specifically. Where a container colour already carried hover and
press, only the missing state composites on top -- stacking a four-state overlay
over a working ternary reaches ~0.18, which is the drag token, not focus.

The switch, radio and slider handles had no container colour to extend, so they
take the whole StateOverlay at the AOSP state-layer size for their component:
40dp on the switch and the radio, overhanging their 24dp and 20dp paint the way
M3 draws it, and on the sliders sized off the handle because this file runs at
the 3/4 scale its own header asks for. The radio's hand-mixed `m3onSurface` at
0.1 goes with it -- that was hover at the focus token's value, and the only
state it had.

The M3 Expressive squeeze was already right and running on the wrong spec:
`handlePressedWidth: 1.5` against `3` is Material3 Thumb's `width / 2`, animated
on `elementMoveFast`, an effects spec driving a size. Both sliders' handle and
margin Behaviors are `elementMoveSmall` now, and the track fills -- which had no
colour Behavior at all -- get `elementMoveFast`, which is 9's pairing exactly and
matters most on the vertical one, whose fill swings to `colErrorContainer` past
`to`. `valueAnimationDuration` dies: an exported duration knob with a hard-coded
`Easing.OutCubic`, defaulting to 0 so its own Behavior was disabled, set by no
caller in the shell. So does the value label's `Behavior on y`, which put a
200ms effects spec on a number chasing a handle whose y does not animate, and
`layer.enabled` on the vertical handle, which bought nothing a Rectangle does not
antialias itself and clipped away anything drawn outside a 4dp bar.

Both combo boxes replace one opacity PropertyAnimation -- same duration in both
directions -- with the arrowPopup transcription, `transformOrigin: Item.Top`
because the list drops out of the field, and 9's verylarge radius. Padding goes
8 to 12 for geometry, not taste: at radius 30 the card's left edge at y=8 sits at
x~9.6, so an 8px inset row pokes out through the corner arc. `highlighted` reads
`ListView.view.currentIndex`, not `root.highlightedIndex`, because the search
variant's arrow keys call `incrementCurrentIndex()` and break that binding on the
first keypress -- before this, arrowing through either popup highlighted nothing.

The I-beam is fixed where it belongs. `TextInput`/`TextArea` set no cursor, so
AddressBar and MaterialTextField each laid a hover-enabled MouseArea over the
text; it is a `HoverHandler` in the four text primitives now, and the copies are
gone. A MouseArea would have taken hover off the rows several of these sit in.
MaterialTextArea's indicator reads `activeFocus` rather than `focus`, which is
true for whichever item holds it inside its scope, and thickens 1 to 2 the way an
M3 filled field does. KeyboardKey's `borderRadius: 5` becomes
`rounding.unsharpenmore`, so keycaps stop being the one thing still rounded in
sharp mode.

check-input-states.py holds it: focus has to be a binding whose value reads the
flag, not a mention, which is 3.7's failure mode; disabled has to be the 0.4 on
the whole control; and on a slider the press assertion is the squeeze, because
that is how a slider renders one.
